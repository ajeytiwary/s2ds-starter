# Working as a team

Create an issue with a research question, input data, acceptance criteria and an owner. Use a short branch and a pull request; another student reviews it. Keep commits small. Never commit credentials or identifiable field records. Use `.env` locally (ignored), and document variable names only.

Run `python -m unittest discover -s tests -v` and the demo before requesting review. Explain behavioral changes and evidence in the PR. Record experiments in the template below; do not choose models from test scores. Freeze the site split before experimentation. A mentor owns the final blind evaluation; the workshop fixture has public labels and is not a genuinely blind benchmark.
